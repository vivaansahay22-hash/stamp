# Economic Model

VERITY is designed around the idea that attackers should pay a meaningful cost when creating many credentials. In the prototype, a credential requires a single enrollment assessment that takes approximately 15–20 minutes of effort. A small number of credentials is manageable for a legitimate user, but creating dozens or hundreds produces a large operational burden.

This is not a mathematical guarantee of safety. Attackers may:

- automate parts of the enrollment flow
- outsource the effort to labor markets
- parallelize across devices
- steal or borrow credentials
- find implementation weaknesses

The point is not perfect security; it is to increase attacker cost while making legitimate usage cheap and mostly invisible. That shifts the economics away from repeated daily friction for users and toward economic pressure against automated abuse.
